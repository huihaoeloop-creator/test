# 风格解构

```
python -X utf8 scripts/decompose.py --plan plan.json --assets 02-assets/ -o 03-style/
```

## 这个节点只做算得出来的部分

| 算得出来 | 怎么算的 |
|---|---|
| 配色 | 从图里量化提取 |
| 高频词 | 统计商品标题 |
| 渠道构成 / 图量 | 数台账 |

| 算不出来 | 为什么 |
|---|---|
| 廓形、领型、克重、工艺、袖型、长度 | **要看图，脚本看不了** |

算不出来的留空标「待填」。**不要为了让表看起来完整就编一个。** 脚本编一个
「Oversized」出来，节点 04 的 prompt、节点 05 的几十张图全跟着跑偏，
而且没人会发现那是编的。

填法：直接改 `03-style/style.json` 里每个方向的 `judgement`。**重跑不会清空
已填的项**——这一点是特意做的，不然每收一批新图就得重填一遍。

## 配色靠不靠得住，脚本自己会说

产品图基本是白底棚拍，直接量化白色会吃掉一大半。所以只取中央那块，
再把接近纯白的丢掉。

代价是：**白色和米色的款会被一起丢掉**。所以脚本记着丢了多少，丢太多就提示：

```
⚠ 平均 70% 的像素是白底被丢掉的。如果这批本来就是白色/米色的款，
  这份配色会偏——人工核一眼
```

看到这条就去翻几张原图。**宁可提示不准，也不要悄悄给一份错的配色。**

## 高频词是采集有没有跑偏的交叉检查

方向叫「Statement Colour」，检索词是 intarsia / stripe / argyle，结果收回来的
图标题里一次都没出现：

```
⚠ 方向词一次没出现：intarsia、stripe、argyle、saturated
  —— 采集可能跑偏了，回节点 02 看看
```

**这时候该回节点 02 重收，不是硬着头皮往下走。** 素材不对，后面做得再漂亮
也是错的。

注意它只看**标题文字**——淘宝的标题词多、Pinterest 的常常是空的。某个渠道
占比高但标题都是空的，这个检查就失灵，别把它当唯一依据。

## 边界

- 有方向还没收到图时，先回节点 02 收齐再解构。
- 配色是**素材的**配色，不等于**提案的**配色。提案要提什么色是设计判断，
  在待填项里体现，不是把提取结果直接当结论。
