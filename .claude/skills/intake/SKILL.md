# 需求接单

把一句话需求变成可签字的《需求确认单》。**这一步的全部价值在于不猜。**

需求歧义在这里花五分钟澄清，比第 5 节点（批量生图）返工两小时便宜。填错一个
字段，后面的检索词、prompt、出图全部跑偏。

## 步骤

0. **开单先给 `--tag` 和 `--requester`：**
   ```
   python -X utf8 scripts/intake.py --new --tag SEED --requester 陈主管 -o intake.json
   ```
   一位主管一天可能开好几张单。不给 `--tag`，两张单会拿到同一个 `req_id`，
   历史相似度检索会把它们当成同一张跳过。放进 `projects/<req_id>/00-brief/`。

1. **原话原样抄进 `raw_request`**，不要改写、不要润色。后面对不上时要靠它回溯。

2. **能确定的字段才填。** 字段清单跑 `python scripts/intake.py --fields` 看。
   - `required`（品类/季节/交付日）缺了不能开工
   - `key`（廓形/色彩/面料/客群/价格带）缺了会跑偏，脚本会自动列进待确认项
   - 从原话里推得出的就填；**推不出的一律留空**，不要填一个"看起来合理"的值

3. **把语义歧义写进 `open_questions`。** 脚本只能发现"字段没填"这种机械缺失，
   判断不了"这个词有两种理解"。这类必须你来提，通常 3-5 条。举例：
   - 「Y2K」指 2000 年代初的金属感未来主义，还是低腰辣妹风？两个方向差很远
   - 「下周要」是下周一还是下周五？
   - 「跟上次那个类似」——上次是哪一单？
   - 「高级感」是指面料克重和工艺，还是配色和廓形？

   提问要给出**选项**，别只说"请明确"——陈主管选 A 或 B 比让他从头描述快得多。

4. **跑校验，把确认单发给陈主管：**
   ```
   python -X utf8 scripts/intake.py intake.json --history projects/
   ```
   `--history` 会找出同品类同季节的历史单，附上当时采纳的方向。相似案例常常
   直接省掉一轮检索。

5. **陈主管逐条回复后**，把答案填回字段、清空已解决的 `open_questions`，重跑校验。
   全部清掉了再进节点 01。

6. **转下游：**
   ```
   python -X utf8 scripts/intake.py intake.json --to-brief brief.json
   ```
   只覆盖 `meta` 和 `brief`，brief.json 里已有的 recommendations、sources 等
   原样保留。

## 边界

- **不要替陈主管做审美或商业判断**——不猜品牌调性、不猜客户偏好、不猜价格带。
- **不要为了让单子看起来完整而填空**。留白 + 一条明确的问题，比一个编出来的
  值有用得多。
- 必填项缺失时脚本以退出码 1 失败，**这是设计如此**，不要绕过去。
