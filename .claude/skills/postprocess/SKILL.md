# 后期处理

```
python -X utf8 scripts/postprocess.py --in 生成图/ --out 06-clean/ --into brief.json
```

跑完 `brief.json` 里的 `recommendations` 就填好了，直接接节点 07。

## 抠背景只用 Pillow，不装 rembg

这条流程的图是**白底棚拍**（节点 04 的 prompt 里写死了
`plain seamless white studio background`），背景均匀且连通到画面边缘。
这种图用「从边缘漫填」比跑分割模型更准，也不用下 170MB 权重。

关键是两步，缺一不可：

1. 跟边缘取到的背景色比，颜色接近的算「像背景」
2. **只保留连通到画面边缘的那部分**

第 2 步是为白/米色衣服准备的：白毛衣身上的白和背景一样接近，但它不连到边缘。
不过**衣服直接挨着背景、颜色又在容差内时，漫填还是会漏进去**——这种要调容差，
见下面。

## 三个警告，各自的意思不一样

| 警告 | 什么情况 | 怎么办 |
|---|---|---|
| `只去掉 3% 以下` | 底色跟衣服太像，或者根本不是纯色底 | 调大 `--tolerance` |
| `去掉了 90% 以上` | 把衣服一起抠了 | **调小** `--tolerance`。白/米色款常见 |
| `四边只有 X% 被判成背景` | 底不均匀：渐变、场景、光斑 | **调容差没用**，得换白底重生 |

第三条最要紧，因为**光看「去掉了百分之几」发现不了**：渐变底能去掉 54%，
数字看着很正常，实际边上留了一圈。

实测：白毛衣默认容差 18 → 去掉 92%（衣服没了）；调到 3 → 干净，
非白像素占比跟彩色款一样是 26%。

## 正反配对不靠排序

文件名里有 `front`/`back`、`正`/`反`、`_f`/`_b` 就按标记配；**一个标记都没有
才退回「排序后两两配」，并且明说这是猜的**。

配错了整页正反颠倒，在 PPT 里一眼看不出来——所以宁可啰嗦。

输出命名是 `<款号>_1_front.jpg` / `<款号>_2_back.jpg`。带顺序号是因为节点 07
的 `--pair` 靠文件名排序配对，而 `001_b` 排在 `001_f` 前面，**不带顺序号
正反就是反的**。

## 画幅统一是补边不是裁切

两张图并排放，画幅不一致会一张顶天一张缩在中间。默认补到 3:4。

**补边不裁切**——裁切会切掉下摆或肩线，那是判断款式的关键部位。
不想补边用 `--canvas none`。

## 边界

- `--alpha` 另存一份透明底 PNG，需要往别的背景上合成时用。**交付 PPT 用白底
  JPG**，透明 PNG 在 PowerPoint 里更容易出问题。
- `--into` 写进 brief.json 的路径是**相对 brief 的位置**，整个项目目录拷到
  别的机器上还能用。
- 缺一张的款会点名。**正反必须成对**，缺的那张回节点 05 补生，不要用别的款凑。
