这一版合并了什么，改了什么

《佘吉设计工作流 V1》（九节点技术方案）与《外贸设计开发流程 V2.0》（四阶段业务方案）本来就是同一个项目的两个视角，此版合为一份。两份旧稿到此作废，以本稿为准。

合并时发现五处互相矛盾，按已经跑通的实现定稿，没有含糊并存：

  • 采集渠道：V2.0 写「Agent 自动遍历品牌官网、WGSN、Instagram、Pinterest」——WGSN 和 Instagram 的 ToS 禁止自动抓取，佘吉只出选品清单。已按此改写。
  • Agent 耗时：V2.0 的「约 1 小时全自动」建立在四渠道全自动的前提上。实际有三个人工渠道 + Midjourney 需人工粘贴，时间表按人工节奏重算。
  • 生图主力：V2.0 以 Midjourney 为衍生主力——MJ 没有官方 API，第三方中转违反 ToS。主力改为 Ideogram（公司已有专业版月付）。
  • 抠图方案：V1 建议 rembg。实测机器上没有 rembg / numpy / OpenCV，改用 Pillow 的边缘漫填，对白底棚拍图反而更准。
  • 关卡数量：V1 说八道、V2.0 说三道。改为 3 道主关卡（主管坐下来看）+ 5 道文件级确认（改一个 flag），不再两套说法。

前置共识

先把佘吉的边界钉死

这三条不先说清楚，后面每个节点的验收都会跑偏——最常见的失败是佘吉开始替人做审美判断，或者把挑图的苦力转嫁给主管。

佘吉做：可穷举的机械劳动

检索词中英展开、跨站采集与去重、要素打标、prompt 批量生成、抠图与规格统一、按模板灌 PPT、参数与来源留痕。

佘吉不做：审美与商业判断

哪张图「像这个品牌」、哪个方向「客户会买单」、要不要为成本换面料——全部由主管定。佘吉只把候选整理成编号清晰、可一眼比对的选择题。

佘吉必须留痕：来源与授权

每张素材强制记录来源、渠道、采集时间、可否进交付件。渠道不在已知授权表里的，标 license_checked:false，每次对账都点名。

两个视角

主管看四阶段，佘吉跑九节点

同一条流程的两种说法。主管只需要知道自己什么时候要看、看什么；九个节点是佘吉内部的执行粒度。

拆解

逐节点：输入、动作、产出

每个关卡的产出物都必须「一屏看完」。让主管翻二十个文件夹的关卡，等于没设关卡。

00INTAKE

需求接单与结构化

intake.py

输入

主管一句话需求，通常含糊：「Seed 女装做一个秋冬的趋势和款式推荐」。

佘吉动作

  • 原话原样抄进 raw_request，不改写
  • 拆成结构化字段；推不出的一律留空，不编
  • 比对历史单，标出相似案例与当时采纳的方向
  • 主动列 3–5 条待确认歧义项，每条带选项

产出物

《需求确认单》：我的理解 + 待确认项 + 相似历史案例。
必填项缺失时退出码 1。

01PLAN

检索策略

search_plan.py

输入

已确认的需求单。

佘吉动作

  • 中→英检索词矩阵；查不到的不猜，列进「需补英文」
  • 中文平台（淘宝、小红书）用英→中反查，同义词都给（绞花/麻花）
  • 按趋势方向拆检索式，按渠道分配配额
  • 给每个人工渠道自动生成选品清单

产出物

plan.json（approved:false 出厂）+ 各人工渠道的 picklist-*.md。

02COLLECT

素材采集与出处台账

collect.py · brand_collect.mjs

输入

已批准的 plan.json；主管打包的 zip（文件夹名就是渠道名）。

佘吉动作

  • 客户/对标官网：Playwright 采集，先读 robots.txt，Disallow 就不抓，无绕过开关
  • 按商品名撞方向检索词自动归类；撞不上的进「待归类」，不瞎猜
  • sha256 跨渠道去重；统一改名 <渠道>_<哈希>
  • 逐张登记出处；批次链接不冒充逐张出处

产出物

ledger.json 台账 + 分方向素材目录。--check 三向对账，--handoff 导给主管的图。

03DECODE

风格解构

decompose.py

输入

台账 + 素材图。

佘吉动作

  • 算得出来的：配色（避开白底提取）、高频词、渠道构成
  • 算不出来的留空：廓形、领型、克重、工艺、袖型、长度——要看图
  • 配色可信度自检：白底丢太多会明说「这份配色会偏」
  • 高频词做采集跑偏的交叉检查

产出物

style.json。待填项由人补，重跑不清空已填的。

04PROMPT

出图指令

prompts.py

输入

已补齐的 style.json。

佘吉动作

  • 一款两条：正面 + 背面，成对生成
  • 四款靠方向检索词轮换 + 主色轮换区分，两个轴都来自已批准的数据
  • 配色 hex 转形容词（#BFB7AA → muted light beige），固定映射
  • 按工具出不同文件，显式写 negative 与参数

产出物

prompts.json + 每工具一份 txt。风格要素没填全则退出码 1。

05GENERATE

两拍式批量生成

未建

输入

已审 prompt 包。

计划动作

  • 第一拍：每方向 4 张试水，立即送审
  • 第二拍：只对通过的方向放量
  • Ideogram 走官方 API（IDEOGRAM_API_KEY 环境变量）
  • Midjourney 人工粘贴后回灌，佘吉负责收图与登记
  • 记录 seed 与参数，任意一张可复现

产出物

生图结果 + params.json 参数台账。

06RETOUCH

抠图与规格统一

postprocess.py

输入

选定的出图。

佘吉动作

  • Pillow 边缘漫填抠背景，只保留连通到画面边缘的部分——白毛衣才留得住
  • 三项自检：去太少 / 去太多 / 四边被判为背景的比例
  • 画幅统一是补边不裁切，裁切会切掉下摆和肩线
  • 正反配对优先认文件名标记，退回排序配对时明说是猜的

产出物

白底 JPG（可选透明 PNG）+ 写进 brief.json 的 recommendations，路径相对 brief。

07COMPOSE

按模板组稿

build_deck.py

输入

brief.json + 主管的 .potx 模版。

佘吉动作

  • python-pptx 读模板灌内容，不新建版式、不改母版
  • 首末页原样保留，内容页在中间增减
  • 字体字号取自模板第二页，标题与「Style」框深拷贝，字节级一致
  • 图片重编码成干净基线 JPEG，避免 PowerPoint 修复提示

产出物

可交付 .pptx。check_pptx.py 八项结构检查。

08LEARN

复盘沉淀

未建 · 非阻塞

输入

各关卡的通过/打回记录、客户最终选定方向。

计划动作

  • 回写哪些 prompt 被采纳、哪些被毙、毙稿理由分布
  • 更新风格库、prompt 库、主管偏好画像
  • 统计各节点耗时与返工次数

工具

生图工具：按授权分工，不是选一个

调研于 2026-09。条款会变，赔偿条款按合同走不按官网宣传走——签约前让法务看一眼。

工具角色接入关键事实
Ideogram主力出款图官方 API 公司已有专业版月付。付费档含商用授权；Character Reference 可拉正反一致性。约 $0.03–0.10/张
Adobe Firefly交付兜底官方 API 唯一提供 IP 赔偿的一家。真正进客户交付页的图用它最稳
PatternedAI面料花型人工 垂直做无缝循环，可矢量化到 SVG 给印花。这块没有替代品
Midjourney概念发散人工粘贴 没有官方 API。第三方中转与 Discord self-bot 违反双方 ToS，封号是真的
即梦 AI中文提示词人工 授权书可批量下载，对交付实用。API 走火山方舟，接入成本另算。中文 prompt 生成尚未实现
Leonardo 免费档不用 平台保留对生成图的使用、复制、修改、分发权利，不能用于客户交付。要用须上付费档
Stable Diffusion 自建暂不 唯一能完全离线、数据不出公司。要 GPU 与运维，各版本权重商用条款不同（SDXL≠SD3）

协同

关卡怎么真正落地

写一句「需人工确认」是没用的，人会疲劳、会点「都行」。关卡靠三个机械约束撑住。

约束一：动作只有三个

通过 / 打回 / 换方向。不接受「差不多吧」「你再看着弄」。三选一，佘吉才知道走哪条回退路径。

约束二：打回带结构化理由

勾选式不写作文：廓形不对 / 颜色不对 / 太商务 / 不像该品牌 / 工艺做不出来。这些勾选项是节点 08 唯一的学习燃料。

约束三：一屏可审

产出物必须一屏看完且带编号。需要翻文件夹、要放大才能比对的关卡，实际上等于没有关卡。

配套看板可本地部署（serve.py，纯标准库）：数据不出公司，实时进度 + 素材缩略图，主管浏览器打开即可。部署那台机器不需要装 Claude，只要 Python。

红线

这五条写进流程，不是写进备忘录

违反任何一条，出事的是公司不是工具

  1. 订阅站与社交平台不做自动抓取。WGSN / Fashion Snoops / Instagram / 淘宝 / 小红书，ToS 均禁止。佘吉的职责边界到「生成选品清单」为止。给账号密码不能让这件事变合规，只是把风险转移到你们账号上。
  2. 品牌官网图仅作内部参考。可进灵感页并标注出处，绝不可出现在交付给客户的原创方案页里。这是最容易出事也最容易被忽略的一条。
  3. 小红书笔记图绝不进任何交付物。个人创作者作品，搬运与洗稿的法律风险是实的。
  4. 生图工具商用授权逐个确认。各家条款不同且随订阅等级变化。进交付件的图优先用 Firefly。
  5. 没查过授权的渠道一律标记。主管临时给的图若来自未知站点，照收但标 license_checked:false，每次对账都点名，直到有人确认。没查过 ≠ 能用。
